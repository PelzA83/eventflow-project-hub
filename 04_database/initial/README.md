
# EventFlow — Initial SQL Archive

> Описание первоначального SQL-архива.
> Последнее обновление: 11 ноября 2026 года.

## 1. Назначение

В этом разделе приватного репозитория `eventflow-project-docs` хранится первоначальный набор SQL-файлов EventFlow.

Архив предназначен для:
- изучения первоначальной структуры базы;
- восстановления истории разработки;
- анализа ранее созданных функций;
- изучения диагностических запросов;
- понимания первоначальных сценариев RSVP.

Архив не является актуальной миграцией базы данных.

## 3. Важные ограничения

**Не запускайте весь архив последовательно на действующей базе Supabase.**

Архив отражает историческое состояние проекта.

Известные особенности:

- `01_database_schema.sql` содержит индекс `idx_rsvp_guest`, который позднее был удалён из рабочей базы как дублирующий.
- `02_seed_data.sql` содержит демонстрационные записи. Повторный запуск может создать дубликаты.
- определения функций могут отличаться от актуальных версий;
- диагностические запросы отражают конкретный момент истории разработки.

## 4. Историческая модель RSVP

В архиве сохранены определения:

### get_invitation(p_token text)

Функция получения данных приглашения по токену доступа.

Историческая версия использует SQL, `STABLE`, `SECURITY DEFINER` и пустой `search_path`.

### submit_rsvp(p_token text, p_responses jsonb, p_comment text DEFAULT NULL)

Функция обработки ответов гостей.

Историческая версия использует PL/pgSQL и `SECURITY DEFINER`.

В ней предусмотрены:
- проверка входного JSON;
- проверка токена;
- блокировка группы и мероприятия;
- проверка статуса и срока мероприятия;
- проверка принадлежности гостей к группе;
- создание или обновление RSVP.

Перед использованием этих функций необходимо получить актуальные определения из Supabase.

## 5. Результат исторических RSVP-тестов

В сохранённых материалах зафиксирован следующий результат:

| Показатель | Значение |
|---|---:|
| Всего гостей | 3 |
| Всего RSVP-записей | 3 |
| Подтвердили участие | 3 |
| Отказались | 0 |
| Ожидают ответа | 0 |

Это результат исторического тестового набора, а не подтверждение текущего состояния приложения.

## 6. Правила использования архива

Перед выполнением любого SQL из этого раздела:

1. Проверить актуальную схему базы.
2. Проверить существование объектов.
3. Проверить зависимости и права.
4. Определить возможное влияние на данные.
5. При необходимости адаптировать запрос для текущей среды.
6. Выполнять проверку в безопасной среде.

Не заменять актуальные функции историческими версиями без отдельного согласования.

## 7. Автоматическая проверка

SQL-файлы проверяются SQLFluff Parse с диалектом PostgreSQL в GitHub Actions.

Проверка синтаксического разбора не является подтверждением успешного выполнения запросов в Supabase.
